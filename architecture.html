Architecture

CalBridge is a multi-tenant client portal built on Node.js/Express with Snowflake as the data warehouse. Each client's Amazon data is ingested, stored, and analyzed independently.

Overview

The portal allows CalBridge clients to:

  1. Create an account at app.teamcalbridge.com
  2. Self-connect Amazon Advertising and/or Seller/Vendor Central via OAuth
  3. View advertising performance and contribution margin data
  4. Receive AI-driven decisioning insights to maximize profitability

Authentication Flow

  1. Client signs up at /auth/signup → session created
  2. Client clicks "Connect Amazon Ads" → redirected to /amazon/connect/ads
  3. Server generates OAuth state token, redirects to Amazon LWA consent screen
  4. Amazon redirects back to /amazon/callback/ads with auth code
  5. Server exchanges code for access + refresh tokens
  6. Tokens stored against client_id in Snowflake amazon_connections table
  7. All subsequent API calls use stored tokens (auto-refreshed on expiry)

Same flow for SP-API via /amazon/connect/seller|vendor. Admin auth is a separate session under req.session.adminId.

Multi-Tenancy

Every record in every table is scoped to a client_id. No client can ever see another's data. Enforced at:

  • Session layer: req.session.clientId set on login, never overridable
  • Route layer: requireAuth middleware on all client routes
  • Service layer: all service functions take clientId as first param
  • Snowflake layer: all tables have client_id column; all queries filter by it

Contribution Margin Model

The CM waterfall breaks revenue down into profit tiers:

TierFormulaMeaning
RevenueSeller ordered revenue + Vendor shipped revenueTop-line sales
CM1Revenue − COGSGross margin — is the product priced right?
CM2CM1 − FBA Fees − Referral FeesMargin after Amazon takes its cut
CM3CM2 − Ad SpendTrue profitability — what you actually keep

Proportional Ad Spend Attribution

Ad spend is distributed per ASIN proportionally by revenue share each day:

ASIN Ad Spend = (ASIN Revenue / Total Day Revenue) × Total Day Ad Spend

This ensures each ASIN receives a fair share of ad spend based on its contribution to daily revenue, rather than applying total ad spend uniformly.

Break-Even ACOS

Break-Even ACOS = CM2 / Revenue = (Revenue - COGS - FBA Fees) / Revenue Example: Revenue: $50 · COGS: $10 · FBA Fees: $8 CM2 = $32 → Break-Even ACOS = 32/50 = 64% If actual ACOS > 64%, the product loses money on ads. If actual ACOS < 64%, there's headroom to spend more profitably.

Decision Engine

The decision engine (src/services/decisionEngine.js) runs on every dashboard load and surfaces:

  • 🔴 Negative CM3 — losing money on every sale
  • 🔴 Spend with no sales — wasted campaign spend (>$100, 0 sales)
  • 🟡 ACOS above break-even — profitable but ads eating margin
  • 🟡 High ACOS campaign — campaign ACOS > 60%
  • 🟡 ACOS spike — 3-day rolling ACOS > 120% of 7-day baseline
  • 🟡 Budget over-pacing — projected month-end spend >110% of budget
  • 🟡 Budget under-pacing — projected month-end spend <70% of budget
  • 🟢 Scale opportunity — CM3% >15% and ACOS <50% of break-even

Data Ingestion

Data is pulled from Amazon APIs on a 6-hour schedule via src/jobs/scheduler.js:

  1. Sales data — Seller/Vendor Central reporting APIs
  2. Ad performance — Amazon Advertising API (campaigns, ad groups, keywords)
  3. Products — ASIN catalog with COGS from client upload
  4. Contribution Margin — Calculated from sales + ad_performance + products

All jobs wrap in runJob() from ingestionRunner.js which provides retry logic (3 retries with exponential backoff), logging to ingestion_log table, and failure email alerts.
